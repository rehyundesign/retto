# 클릭하면 어디로 가는가

어느 세션을 고르고, 어느 앱으로 데려가고, 그 앱에서 어떻게 그 대화를 되살리는가.

## 어느 세션을 보여줄지

Claude Code 확장은 세션 상태를 셋으로만 보고하고, 사이드바 아이콘의 파란 숫자는 그중 하나의 개수다.

```js
// state: J0(["idle","running","waiting_input"])
updateSessionListBadge($) {
  let Q = $.filter(J => J.state === "waiting_input").length
  this.sessionListView.badge = Q > 0 ? { tooltip: `${Q} session… waiting for input`, value: Q } : { value: 0 }
}
```

`waiting_input` 은 권한·질문 대기만이 아니라 턴이 끝나 답을 기다리는 상태까지 포함한다. 훅이 만드는
우리 상태로는 `waiting`·`failed`·`waving` 세 가지가 그 묶음이고(`needsInputStates`), 이 셋을
`running`·`review` 보다 위에 둔다. 예전에는 `waving`(답변 완료)이 `running` 아래여서 파란 숫자가
떠도 작업 중인 세션에 가려졌다.

## 세션으로 데려가는 방법

딥링크 `vscode://anthropic.claude-code/open?session=<id>` 는 확장의 URI 핸들러에서
`claude-vscode.primaryEditor.open` → `createPanel()` 로 들어간다.

```js
if ($) { let V = this.sessionPanels.get($); if (V) { V.reveal(); return } }
… createWebviewPanel("claudeVSCodePanel", "Claude Code", …)   // 없으면 새 패널
```

`sessionPanels` 에 등록되는 건 에디터 패널 세션뿐이다. 사이드바 뷰(`resolveWebviewView`)의
세션 콜백은 `updateSessionState(...)` 만 부르고 그 맵을 건드리지 않으며, 맵 자체가 창(확장 호스트)마다
따로다. 그래서 사이드바에서 돌던 세션이나 다른 창의 세션은 딥링크로 되살릴 수 없고, 같은 대화가
새 패널로 한 번 더 열린다. 확장이 노출하는 URI 는 `/open` 과 `/install-plugin` 둘뿐이라 이걸
URI 로 우회할 방법은 없다.

그래서 순서를 둘로 나눈다.

1. `NSWorkspace.open([cwd], withApplicationAt: VSCode)` 로 **그 세션의 작업 폴더 창을 앞으로** 보낸다.
   이미 그 폴더를 열어 둔 창이 있으면 VS Code 가 그 창을 앞으로 가져오고 새 창을 만들지 않는다.
2. 창이 자리 잡은 뒤(0.45초, 앱을 새로 띄웠으면 2.5초) 딥링크를 보낸다. 이제 그 URI 를 받는 창이
   세션을 가진 창이므로 `sessionPanels.get(id)` 이 맞아 `V.reveal()` 로 **그 탭이 되살아난다**.

창을 먼저 보내지 않으면 URI 가 마지막으로 활성화된 창에 배달되고, 그 창에는 그 세션이 없으니
같은 대화가 새 패널로 한 번 더 열린다. 이게 "클릭하면 새 섹션이 열린다"의 정체였다.
`claudeCode.preferredLocation` 이 `sidebar` 인 경우에는 2단계가 탭을 만들기만 하므로,
창만 앞으로 보내려면 ⌥ 를 누른 채 클릭한다.

## VS Code 와 Claude 앱을 같이 쓴다

훅은 VS Code 것이 아니다. `~/.claude/settings.json`(유저 전역)에 들어가고 `~/.claude/retto-pet/hook.cjs`
를 절대경로 node 로 부른다. Claude 데스크탑 앱도 Claude Code 세션을 `settingSources: ["user","project","local"]`
로 띄우므로(앱 번들 `app.asar` 에서 확인) 같은 훅이 그대로 돈다. VS Code 확장은 그 훅을 설치해 주는
버튼일 뿐이라, 설치가 끝났으면 확장 없이도 상태 추적·말풍선·배지가 다 동작한다.

갈리는 건 **클릭했을 때 어디로 데려가는가** 하나다. 그래서 훅이 세션마다 어디서 왔는지 적는다.
훅은 Claude Code 프로세스의 자식이라 `CLAUDE_CODE_ENTRYPOINT` 를 그대로 물려받는다.

| `CLAUDE_CODE_ENTRYPOINT` | `client` | 어디로 |
|---|---|---|
| `claude-vscode` | `vscode` | VS Code |
| `claude-desktop` | `claude` | Claude 앱 |
| 그 밖의 값(`sdk-ts` 등) | `claude` | Claude 앱 |
| `orca` | `orca` | Orca 의 그 채팅 탭 (아래 「Orca 에서 띄운 세션」) |
| `cli` · 빈 값 | `cli` · `` | VS Code |

`claude-desktop` 은 **실측값**이다. 앱 번들(`app.asar`)만 읽으면 SDK 기본값 `sdk-ts` 로 떨어질 것처럼
보이는데, 실제로 데스크탑 앱에서 세션을 돌려 보면 이 값을 박는다. 코드를 읽어 짐작한 값과 달랐다.

`CLAUDE_CODE_EXECPATH` 에 `.vscode` 가 있는지도 잠깐 봤는데, 그건 Cursor 같은 포크를 가려내려던
것이었다. 포크를 빼기로 하면서 근거가 사라졌고 판별만 흐렸다. 이름으로 확실히 가려지는 건 VS Code 뿐이라,
모르는 호스트는 VS Code 가 아닌 쪽으로 본다.

터미널(`cli`)은 `client` 로는 구분해 두되 여는 건 VS Code 로 보낸다. 돌아가는 터미널 세션을 되살릴
방법이 없어서다 — `claude --resume` 은 그 세션으로 가는 게 아니라 프로세스를 하나 더 만드는 일이다.

값을 못 읽은 훅 한 번이 이미 알아낸 값을 지우면 그 세션 클릭이 그때부터 엉뚱한 앱으로 가므로,
빈 값은 이전 값을 덮지 않는다. 반대로 같은 세션이 VS Code 와 Claude 앱 양쪽에 열리면(딥링크로 그렇게 된다)
마지막에 쓴 쪽이 이긴다 — 지금 그 세션이 실제로 사는 곳이 마지막에 쓴 쪽이므로 그게 맞다.

## Orca 에서 띄운 세션

Orca 는 Claude Code·Codex 를 자기 채팅 탭이나 터미널 탭 안에서 띄운다. 레토는 그 소식을 예전부터
받았지만 출처를 몰라서, Claude 채팅은 `CLAUDE_CODE_ENTRYPOINT=orca` 가 `vscode` 가 아니라는 이유로
Claude 앱으로, Codex 채팅은 Codex 앱으로 보냈다. 눌러도 Orca 의 그 탭으로 가지 않았다.

**알아보는 방법은 셋이다.**

| 세션 | 근거 | 레토가 적는 값 |
|---|---|---|
| Orca 의 Claude 채팅 | 훅이 받는 `CLAUDE_CODE_ENTRYPOINT=orca` · `ORCA_AGENT_SESSION_ID` | `client: orca` · `orcaSessionId` |
| Orca 터미널 탭의 Claude | `CLAUDE_CODE_ENTRYPOINT=cli` · `ORCA_TERMINAL_HANDLE` | `client: cli` · `orcaTerminalHandle` |
| Orca 의 Codex 채팅 | 롤아웃 첫 줄(session_meta)의 `originator: "orca_desktop"` | 화면 상태에서만 `orcaHosted` |

Codex 쪽에 훅 값이 없는 이유는 Orca 가 자기가 띄운 Codex 에 `-c hooks.state=…enabled=false` 를 넘겨
`~/.codex/hooks.json` 훅을 끄기 때문이다(2026-11-13, Orca 1.4.257 의 `codex app-server` 실행 인수에서 확인).
레토 훅도 함께 꺼지므로 롤아웃으로 알아본다.

**입력·승인 대기는 Orca 에 직접 묻는다.** 롤아웃에는 승인 요청이 남지 않는다 — 권한 상승을 요청한 도구 호출만
남고 결과가 안 붙은 채 멈춰 있어서, 오래 걸리는 명령과 구분이 안 된다. 대신 Orca 가 채팅 탭마다 붙여 두는
상태(`session.tabs.listAll` 의 `chatStatus.state`)를 읽는다(`OrcaSessions.swift` 의 `OrcaChatStatusReader`).

| Orca 상태 | 뜻 | 레토 |
|---|---|---|
| `blocked` | 승인·질문이 걸려 있거나, 턴이 내 답을 기다리며 끝났다 | 입력 대기 |
| `waiting` | 터미널 훅 경로의 권한·질문 대기 | 입력 대기 |
| `working` · `done` · `idle` | 그 밖 | 롤아웃 상태 그대로 |

- 실패는 `done` + `mainAgent.outcome: "failure"` 로 와서 `blocked` 와 겹치지 않는다
  (Orca 1.4.257 `out/main/index.js` 의 채팅 상태 계산 — 질문이면 `blocked`, `awaitingUser` 로 끝난 턴도 `blocked`)
- 2026-11-13 실측: 「ask」 권한 Codex 채팅에 권한 상승이 필요한 명령을 시키자 `working` → `blocked`,
  롤아웃은 그동안 결과 없는 도구 호출에서 멈춰 있었다. Orca 기본값인 「full-access」 채팅은 승인을 묻지 않는다
- **탭과 스레드 잇기.** 탭에는 Codex 스레드 ID 가 없다. Orca 세션 기록 `agent-session-journal.db` 의
  `agent_session_records.record_json` → `providerHandleChain[].handle.threadId` 를 읽기 전용으로 열어 잇는다.
  이을 수 없거나 두 탭이 한 스레드를 가리키면 그 채팅은 버린다 — 다른 스레드를 파랗게 칠하지 않는다.
  이은 Orca 세션 ID 로 누르면 같은 워크스페이스에 Codex 채팅이 여럿이어도 그 탭으로 간다
- **언제 묻나.** Orca 가 켜져 있고, Orca 의 Codex 채팅이 작업 중이거나 대기 중일 때만 3초마다 묻는다.
  Orca 를 켜지 않는다. 한 번에 Orca 의 Electron 을 node 로 0.29초 띄운다(최대 메모리 89MB, 2026-11-13 측정)
- **못 읽으면** 지난 값을 들고 있지 않고 롤아웃 상태로 돌아간다. 승인이 끝났는데 입력 대기가 남는 것보다
  대기를 몇 초 늦게 아는 쪽을 골랐다. 다음 조회 전에 롤아웃이 턴 완료를 먼저 알리면 지난 대기를 다시 띄우지 않는다
- 응답·승인을 보내거나 기록을 쓰지 않는다. 읽는 것은 탭 상태와 세션 기록의 스레드 ID 뿐이다

**Orca 업데이트 때 확인할 것.** 런타임 클라이언트와 세션 기록은 공개 API 가 아니다.
① `session.tabs.listAll` 의 `chatStatus.state` 값 이름 ② `agent_session_records` 표와 `providerHandleChain` 모양
③ Electron 의 `node:sqlite`(Orca 1.4.257 은 Node 24.22.1). 하나라도 바뀌면 판독기는 아무것도 내지 않고
롤아웃 상태만 남는다 — 다시 예전처럼 작업 중·완료만 보인다.

`ORCA_*` 변수는 Orca 터미널에서 띄운 다른 앱(VS Code 등)에도 물려 갈 수 있다. 그래서 Claude 는
entrypoint 가 `orca`·`cli` 일 때만 이 값을 받는다. 모양이 다른 값(`^[A-Za-z0-9_:.-]{1,128}$` 밖)은
잘라 쓰지 않고 버린다 — 잘린 ID 는 다른 탭을 가리킨다.

**데려가는 방법.** `orca://` 링크는 페어링·플러그인용뿐이고, `orca` CLI 에도 채팅 탭을 고르는 명령이 없다
(`terminal switch` 는 터미널 탭 전용). 그래서 CLI 가 쓰는 런타임 클라이언트
(`Orca.app/Contents/Resources/app.asar.unpacked/out/cli/runtime-client.js`)를 Orca 의 Electron 으로 불러
Orca 에 직접 요청한다(`OrcaSessions.swift` 의 `orcaRevealScript`).

1. `session.tabs.listAll` — 워크스페이스별 탭 목록. 채팅 탭 ID 는 `agent-session:<Orca 세션 ID>` 다.
2. 훅이 적은 Orca 세션 ID 로 탭을 찾는다. 없으면(훅 없는 Codex) 작업 폴더가 같은 워크스페이스에서
   같은 종류 채팅이 하나뿐일 때 그 탭을 고른다. 여럿이면 어느 것인지 모르므로 워크스페이스까지만 연다.
3. `worktree.activate` → `session.tabs.activate`, 둘 다 `navigation: "host"`(데스크탑 화면을 옮긴다).

터미널 탭은 공개 CLI `orca terminal switch --terminal <핸들>` 로 연다. 내부 요청이 실패하면 공개 CLI
`orca worktree activate --worktree path:<작업 폴더>` 로 워크스페이스까지 열고, 그것도 안 되면 Orca 를
앞으로 가져오는 것으로 끝낸다. 런타임 클라이언트는 공개 API 가 아니므로 Orca 업데이트로 바뀔 수 있다.
요청은 화면을 옮기는 것뿐이고 대화 내용은 읽지 않는다.

`agentSession.reveal` 도 있지만 채팅을 불러오기만 하고 화면은 옮기지 않는다(실측). 쓰지 않는다.

Orca 세션은 「기본 열기 방식」을 VS Code·Claude 앱으로 고정해도 Orca 로 보낸다. Codex 를 늘 Codex 앱으로
보내는 것과 같은 이유다 — 다른 앱에서는 그 탭을 고를 길이 없다. 작업 메뉴에는 「Orca에서 열기」가 나오고,
Codex 채팅에는 「Codex 앱에서 열기」도 함께 나온다. Claude 의 Orca 채팅은 `~/.claude/sessions` 에
`entrypoint: orca` 로 상태를 남기므로 Claude 앱과 같은 기준으로 작업 중·입력 대기를 표시한다.

## 어디로 데려갈지 고르기

오버레이는 `client` 값으로 앱을 고른다. 메뉴바 **발바닥 → 세션 열 곳**에서 `자동`(기본)·`VS Code`·`Claude 앱`.
자동이 기본인 이유는 둘을 섞어 쓰면 고정값이 반드시 절반을 틀리기 때문이다 — 배지에 셋이 떠 있는데
하나는 VS Code, 하나는 Claude 앱이면 고정으로는 답이 없다. 고정은 자동이 잘못 짚을 때의 탈출구다.

| | VS Code | Claude 앱 |
|---|---|---|
| 딥링크 | `vscode://anthropic.claude-code/open?session=` | `claude://resume?session=` |
| 창 먼저 앞으로 | 필요 (`needsWindowFocusFirst`) — 안 하면 새 패널이 생긴다 | 불필요 — 세션이 창 하나에 모여 있다 |
| 창을 못 찾으면 | 앱만 앞으로 보내고 딥링크는 접는다 | 해당 없음 |

`client` 를 아직 안 적은 옛 세션과 `cli` 는 VS Code 로 간다 — 지금까지의 동작 그대로다.

`claude://resume` 은 앱의 URL 핸들러에서 `importCliSession(sessionId)` 으로 들어간다. 이름이 import 라
VS Code 쪽 `reveal()`(살아 있는 탭 되살리기)과 다른 것 아닌가 걱정했는데, 실제로 눌러 보면 그 세션의
대화가 그대로 열린다. 다만 **앱이 안 떠 있을 때 보낸 첫 URL 은 조용히 버려진다** — 앱이 뜨는 중에
배달되기 때문이다. 그래서 `focusHostApp` 이 앱을 먼저 앞으로 보내고 2.5초(이미 떠 있으면 0.45초)
기다렸다가 딥링크를 보낸다. 이 대기는 원래 VS Code 때문에 넣은 것인데 Claude 앱에도 그대로 필요했다.

의도적으로 다른 세 가지가 있다.

- **반응을 hover 가 아니라 클릭에 걸었다.** 코덱스 펫은 앱 창 안에 있어서 hover 를 반응에 쓸 수 있지만,
  이 오버레이는 창이 레토만 한 크기다. hover 를 점프에 쓰면 마우스를 올릴 때마다 시선 추적을 잃는다.
- **끌 때는 코덱스 펫처럼 끌리는 방향으로 달린다**(아틀라스 행 1·2). 방향은 직전 마우스 위치와의
  차이로 정하고 2pt 이하 떨림은 무시한다 — 안 그러면 좌우가 매 프레임 뒤집힌다. 끄는 동안에는
  시선 추적을 쉬고, 손을 놓으면 원래 동작으로 돌아간다. 원본 행 2 는 얼굴이 칸 밖으로 잘려 있어
  행 1 을 좌우로 뒤집어 다시 만들었다.
- **배지 뒤 블러는 구현하지 않았다.** `NSVisualEffectView` 를 투명 창에 얹어야 해서, 흰 테두리와
  그림자로 유리질 느낌만 냈다.
