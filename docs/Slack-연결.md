# Slack 연결

레토 메뉴 → **Slack 설정…**에서 연결과 알림 범위를 바꾼다. 개인 DM·그룹 DM, 내 사용자 멘션, 추가로 선택한 채널의 모든 새 메시지를 각각 설정한다. 기본값은 DM·멘션 켜기, 추가 채널 없음, 내용 미리보기 켜기다.

## 앱 안의 연결 안내

Slack 설정 창 위쪽의 **처음 연결하시나요? 연결 안내 ↗**를 누르면 기본 브라우저에서 로컬 HTML 안내가 열린다. 전용 앱 만들기, 사용자 토큰 발급, 앱 토큰 발급, 레토 연결을 네 단계로 설명한다. 설정 JSON 복사와 오류별 도움말을 제공하며, 두 토큰 입력 칸에 마우스를 올려도 발급 위치를 확인할 수 있다. 안내에는 실제 토큰이나 계정 정보를 넣지 않으며 외부 스크립트·폰트를 불러오지 않는다.

## 연결 준비

이 버전은 별도 서버 없이 Slack 공식 Socket Mode로 연결한다. 브라우저 로그인만으로 연결하는 OAuth 화면은 포함하지 않는다. 본인만 설치하는 전용 Slack 앱과 같은 앱에서 발급한 두 토큰이 필요하다. 회사 워크스페이스에는 관리자 승인이 필요할 수 있다.

1. [Slack 앱 관리](https://api.slack.com/apps)에서 앱을 만든다. 아래 `slack-app-manifest.json` 내용을 이용해 **From a manifest**로 만들 수 있다.
2. OAuth & Permissions에서 앱을 워크스페이스에 설치하고 **User OAuth Token** (`xoxp-`)을 확인한다. 봇 토큰은 개인 DM을 받는 용도로 쓰지 않는다.
3. Socket Mode를 켠다. Basic Information → App-Level Tokens에서 `connections:write` 권한으로 앱 토큰 (`xapp-`)을 만든다.
4. 레토의 Slack 설정에 두 토큰을 입력하고 **저장하고 연결**을 누른다. 토큰은 채팅이나 문서에 붙이지 않는다.
5. 연결 상태를 확인하고, 다른 사람이 보낸 새 DM이나 내 멘션으로 확인한다. 자신의 메시지는 알리지 않는다.

수동으로 설정한다면 **User Token Scopes**는 `channels:read`, `groups:read`, `im:read`, `mpim:read`, `users:read`, `channels:history`, `groups:history`, `im:history`, `mpim:history`다. **Subscribe to events on behalf of users**는 `message.channels`, `message.groups`, `message.im`, `message.mpim`이다. `app_mention`은 봇 멘션이므로 개인 멘션을 대신하지 않는다. 권한을 변경하면 워크스페이스에 다시 설치한다.

같은 Slack 앱에 여러 사용자를 설치하거나 다른 Socket Mode 클라이언트를 함께 연결하지 않는다. Socket Mode 이벤트는 앱 연결 사이에서 나뉘어 전달될 수 있다. 레토는 선택한 워크스페이스와 사용자 권한에 해당하는 이벤트만 표시한다.

## 표시와 읽음

- Socket 재연결 중에도 기존 알림의 HTTP 읽음 조회를 유지한다. 연결 해제·토큰 교체 때는 이전 조회 결과를 제외한다.
- Slack 앞 창 제목이 연결된 워크스페이스와 DM·채널 이름에 정확히 일치하고 3초 이상 유지되면 해당 대화의 읽음 위치 조회를 앞당긴다. 창 제목만으로 알림을 해제하지 않고 Slack API가 반환한 읽음 위치까지 해제한다. 창 제목은 기존 접근성 권한 또는 화면 기록 권한으로 확인하며, 권한이나 정확한 제목이 없으면 API 읽음 조회를 사용한다. 스레드·그룹 DM·이름이 같은 여러 대화는 창 제목만으로 해제하지 않는다. 확인 중 새 메시지가 오면 확인 시간을 다시 계산한다. 앞 창의 조회 우선순위 갱신은 대상별 5초 간격이며 메서드의 `Retry-After`를 지킨다. 조회 주기는 시스템 실행 시간으로 계산해 시계 변경의 영향을 받지 않는다.


- 읽지 않은 Slack 메시지는 고정된 AI 완료 상태보다 먼저 표시한다. 이름표와 배지는 보라색이다. 이름표에는 `#채널명`, DM에는 `DM · 상대 이름`을 표시하고 본문은 `@보낸 사람 메시지`로 표시한다. 이름을 조회하지 못하면 사용자 ID를 표시한다.
- 레토가 받은 새 메시지는 같은 워크스페이스·대화·스레드·보낸 사람별로 묶어 말풍선과 배지에 표시한다. 같은 사람이 2개를 보내면 알림 한 줄에 `+2`, 3개면 `+3`을 붙인다. 숫자는 묶음의 총 미확인 메시지 수다. 본문은 최신 메시지이며, 클릭하면 묶음의 첫 미확인 메시지를 연다. 배지는 개별 메시지 수 대신 알림 묶음 수를 센다. 확인하지 않은 알림을 최대 최근 100개까지 메모리에 유지한다.
- 메시지를 누르면 `slack://channel` 링크를 Slack 데스크톱 앱에 직접 전달한다. 브라우저를 경유하지 않는다. 워크스페이스·대화 ID와 메시지 시각, 스레드 시각을 링크에 포함한다. 앱이 없거나 실행에 실패하면 알림을 유지한다. 앱 실행 성공은 메시지 화면 표시 성공을 보장하지 않는다.
- 레토에서 메시지를 열거나 메뉴의 표시 지우기를 누르면 해당 묶음의 메시지를 내부 목록에서도 제거한다. Slack 앱을 여는 동안 새로 도착한 메시지는 유지한다. 이미 확인한 알림은 읽음 조회와 100개 제한의 대상에 포함하지 않으며 재전송·수정으로 다시 표시하지 않는다. Slack API로 읽음 상태를 변경하지 않는다. Slack에서 직접 읽은 위치를 조회해 해당 메시지까지 레토 알림에서도 해제한다. DM·채널과 스레드의 읽음 위치를 구분하며, API가 읽음 위치를 제공하지 않거나 권한이 부족하면 알림을 유지한다.
- 읽음 조회는 레토가 보관 중인 알림의 대화만 대상으로 한다. DM·채널은 대상별 15초 간격, 전체 읽음 조회는 2초에 1건으로 순환한다. 대화가 많으면 반영이 더 걸릴 수 있다. 스레드는 `conversations.replies`의 부모 메시지 1건에서 읽음 위치만 사용하며 같은 대상은 15초 뒤에 다시 확인한다. 스레드 전체에 분당 1건을 적용하던 제한을 제거하고, 전체 HTTP 조회를 2초에 1건으로 순환한다. 429 응답에서는 해당 메서드의 `Retry-After`를 따른다. 응답 본문은 디스크에 저장하지 않는다.
- 기존 연결은 DM 읽음 조회를 위해 `im:read`, `mpim:read` 사용자 권한을 추가하고 Slack 앱을 워크스페이스에 다시 설치해야 할 수 있다. 설정 창에 읽음 동기화 문제를 별도로 표시한다. 새 토큰이 발급되면 레토에서 사용자 토큰만 갱신한다.
- Slack에서 삭제된 메시지는 레토에서도 제거한다. 수정된 메시지는 보관 중인 알림의 본문만 갱신하고 새 알림 시각을 만들지 않는다. 내 멘션이 삭제돼 알림 조건에 맞지 않으면 제거한다. 대상 대화·워크스페이스·사용자 권한을 확인하고, 오래된 수정 이벤트는 최신 본문을 덮어쓰지 않는다.
- 미리보기를 끄면 말풍선과 접근성 텍스트에서 메시지 본문을 표시하지 않는다. 본문은 수신 처리를 위해 메모리에 남으며 디스크에는 저장하지 않는다.
- 범위를 끄면 해당 알림을 목록에서 뺀다. 나중에 다시 켜도 지난 메시지를 복구하지 않는다.
- 앱이 종료되었거나 연결이 끊긴 동안의 메시지 이력은 조회하지 않는다. 자동 재연결은 지원하지만 누락 메시지를 복구하지 않는다.
- 인증 오류는 설정에 표시하며 자동 재연결을 멈춘다. 일시적인 연결 오류에는 재시도 간격을 늘리고, API의 HTTP 429에는 `Retry-After`를 적용한다.

## Windows 판

규칙은 같다(`windows/src/slack.js`). 트레이 메뉴 **Slack 설정…**에서 연결한다. 토큰은 키체인 대신 Windows 사용자만 풀 수 있게
암호화(Electron `safeStorage` · DPAPI)해 `%APPDATA%\Retto\slack-credentials.bin` 에 둔다. Slack 창 제목으로 읽음을 앞당기는 기능은
없고 API 읽음 조회로만 해제한다. 자세한 차이는 [Windows 판](windows.md).

## 저장과 해제

토큰은 `com.luxia.retto.slack` 서비스의 macOS 키체인 항목 하나에 함께 저장한다. 사용자 설정에는 알림 범위만 저장한다. 토큰을 저장한 후 입력 필드는 비운다. 연결 후에는 바꿀 토큰만 입력하면 비워 둔 토큰은 기존 값을 유지한다. 애드혹 서명으로 다시 빌드한 앱에서는 키체인 접근 허용을 다시 요청할 수 있다.

**연결 해제**는 이 맥의 토큰과 수신 목록을 삭제한다. Slack 서버의 앱 설치·권한을 취소하지는 않는다. 완전한 권한 철회는 Slack 앱 관리에서 진행한다. 레토의 기존 제거 기능도 키체인 항목을 삭제한다.

## 검증

`Retto --self-test-slack`은 실제 토큰이나 외부 네트워크 없이 사용자·워크스페이스 필터, DM·멘션·채널 선택, 자체 메시지 제외, 기존 알림의 수정·삭제 동기화, 중복 수신, 목록 제한, 미리보기, 메시지 링크, 발신자별 묶음과 개수 표시, 열기 중 새 메시지 보존, 읽음 위치별 해제, 스레드 분리, 지연 수신, 조회 주기와 요청 한도를 검사한다. 로컬 HTTP fixture로 실제 `SlackIntegration`의 인증 이후 소켓 실패 상태, 읽음 위치 수신, 읽음 위치 누락, 권한 부족, 이전 generation 요청 취소를 검사한다. fixture는 사용자 설정이나 키체인을 변경하지 않는다. 실제 계정의 인증·이벤트 전달과 Slack 앱 화면 이동은 별도 연결 후 확인해야 한다.

공식 문서: [Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/), [사용자 대화 목록](https://docs.slack.dev/reference/methods/users.conversations/), [DM 이벤트](https://docs.slack.dev/reference/events/message.im/).

읽음 API 근거: [대화 정보와 last_read](https://docs.slack.dev/reference/methods/conversations.info/), [스레드 부모의 last_read](https://docs.slack.dev/reference/methods/conversations.replies/). `im_marked`·`channel_marked`는 RTM 전용이므로 Socket Mode 이벤트로 구독하지 않는다.

메시지 변경 API 근거: [메시지 삭제](https://docs.slack.dev/reference/events/message/message_deleted/), [메시지 수정](https://docs.slack.dev/reference/events/message/message_changed/).

읽음·수신 진단은 `~/.claude/retto-pet/slack-current.json`에 현재 연결 상태, 키체인 조회 대기·시간 초과 여부, 수신·수락 개수, 보관 중인 메시지 ID·타임스탬프, 최근 읽음 위치 확인 결과만 저장한다(권한 0600). 메시지 본문·토큰·HTTP 헤더·응답 본문은 기록하지 않는다. 키체인 조회가 10초 넘게 끝나지 않으면 메뉴에 연결 확인 필요를 표시하고, 기존 조회가 끝날 때까지 중복 보안 요청을 만들지 않는다. 이 경고는 키체인 권한이나 보호 설정을 변경하지 않는다.

실제 본인 DM을 이용하는 개발 검증은 `Retto --slack-read-probe <본인 DM ID> <UUID>`로 실행한다. 이 실행에서만 인증된 본인이 보낸 고유 테스트 문구 한 건을 3분 이내에 수락하며, 일반 실행은 본인 메시지를 계속 제외한다. 검증 후 테스트 옵션 없이 다시 실행한다. Slack 서버의 읽음 위치는 API로 변경하지 않는다.
