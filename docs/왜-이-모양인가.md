# 왜 이 모양이 됐나

오버레이의 형태와 여러 세션을 다루는 방식을 정할 때 무엇을 버렸는지. 정해진 뒤의 규칙은
[화면에 보이는 것](오버레이.md), 클릭이 가는 곳은 [클릭하면 어디로 가는가](세션-열기.md).

## 조건

에디터 창에 속하지 않으면서 Claude Code 상태를 보여야 한다. 쓰는 사람이 Space 와 전체화면 앱을
계속 오가기 때문이다. 여기서 다섯 가지가 정해진다 — 투명한 네이티브 창, 낮은 CPU, 아무 배경화면
위에서나 읽히는 대비, 타이틀 바 없이 끌 수 있을 것, 네트워크에 기대지 않을 것.

## 형태 — 창이 아니라 인형으로

**고른 것: 돌아다니는 인형.** 스프라이트가 화면의 주인이고 배경은 비어 있다. 상태값은 오트밀색
리본 하나가 받는다. 펫을 대시보드로 만들지 않으면서 상태를 말할 수 있고, 나중에 AI 가 늘어도
리본 한 줄만 바뀐다.

버린 쪽은 크게 둘로 갈린다.

- **틀을 두르는 안** — 데스크탑 카드, 폴라로이드, 구름 바구니. 카드 테두리가 생기는 순간
  레토가 배경화면 위에 얹힌 위젯이 되고, 인형이라는 점이 사라진다
- **화면 구조에 기대는 안** — 고양이 모양 노치, 책상 모서리에 앉히기, 화면 가장자리 독.
  한 대에서는 잘 맞지만 모니터가 둘이거나 Stage Manager 를 쓰면 자리가 어긋난다

메뉴 막대에만 두는 안은 가장 실용적이었지만 펫이 없어진다. 상태 조명이나 커서를 따라다니는 안은
작업 중에 시선을 뺏는다.

## 여러 세션 — 하나만 보여주고, 개수는 배지로

**고른 것: 자동으로 급한 세션을 따라가되 고정할 수 있게.** 순서는 입력 대기 → 실패 → 작업 중 →
완료 → 쉬는 중이다. 발바닥 메뉴에서 아무 세션이나 고정하고 다시 자동으로 되돌릴 수 있다.
여기에 **배지 하나**를 더해 손이 필요한 세션 수를 센다. 평소에는 조용하고, 봐야 할 때만 말한다.

버린 쪽은 전부 같은 이유다 — **여러 개를 동시에 보여주려다 대시보드가 된다.**

- 세션마다 펫을 하나씩 띄우기, 활성 세션을 이름표로 쌓아 보여주기, 화면 가장자리에 세션 아이콘
  줄 세우기 — 작은 배율에서 읽을 수 없게 되거나 다른 창과 부딪힌다
- 레토 주위를 도는 점으로 세션을 표시하는 안은 이름을 붙일 자리가 없어 접근성이 떨어진다
- 훅 이벤트를 옆에 타임라인으로 놓는 안은 늘 떠 있는 오버레이치고 너무 무겁다

화살표로 세션을 돌려 보는 안과 메뉴에서만 고르는 안은 반대로 너무 조용해서, 급한 세션이
가려진 채로 남는다. 그게 배지를 따로 둔 이유다.
